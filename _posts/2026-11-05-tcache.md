# Tcache Poisoning

glibc 2.31 버전에는 0x20 ~ 0x410(24~1032byte)의 요청이 들어오면 가장 먼저 채우는 tcache가 있다. tcache에는 bin이 16바이트 간격으로 64개가 있고, 각 bin당 7개까지 할당이 가능하다. 이 bin이 채워지면 fastbin이나 lagre bin 등등 일반적인 chunk 할당처럼 들어간다. 

또, tcache에 들어간 free 된 chunk는 `cache_entry` 구조체로 관리 되는데, 이를 가리키는 key 값이 적혀있어서 같은 chunk를 tcache에 두 번 넣으려고 하면(Double Free로 간주하여) 막힌다. 단, key 값이 완전히 일치할 때만 Double Free로 감지된다.

어라? 그럼 key 값의 1비트라도 조작이 가능하면 Double Free가 가능하지 않을까??
그럼 key 값을 덮기 위해 알아야 하는 전반적인 Tcache 구조부터 살펴보자.

#### tcache_perthread_struct
```c
tcache_perthread_struct
typedef struct tcache_perthread_struct
{
  char counts[TCACHE_MAX_BINS];  
  tcache_entry *entries[TCACHE_MAX_BINS];
}
```
tcache list를 관리하는 구조체로, 변수conut는 tcache에 몇 개의 chunk가 저장됐는지 나타내고 entries는 tcache_entry의 주소가 저장된다.
또, 크기별 bin 배열을 관리하고 해당 스레드가 처음 tcache를 사용할 떼 힙에 할당된다.
#### tcache_put
```c
tcache_put(mchunkptr chunk, size_t tc_idx) 
{
  tcache_entry *e = (tcache_entry *)chunk2mem(chunk);
  assert(tc_idx < TCACHE_MAX_BINS);
  
 + /* Mark this chunk as "in the tcache" so the test in _int_free will detect a
       double free.  */
 + e->key = tcache;
 
  e->next = tcache->entries[tc_idx];
  tcache->entries[tc_idx] = e;
  ++(tcache->counts[tc_idx]);
}
```
tcache_put은 해제한 청크를 tcache에 추가하는 함수로, 해제되는 chunk의 key에 tcache라는 값을 넣도록 되어있다. 여기서 tcache라는 값은 tcache_perthread_struct라는 구조체를 가리킨다.
tcache에 추가될 chunk의 next에다가 현재 tcache에 있는 chunk를 넣고 나서, 추가될 chunk를 tcache에 추가한다.
그런 뒤 tcache의 count(tcache에 있는 청크의 개수를 나타낸다. chunk가 추가되면 +1, 빠져나가면 -1이고, 0이면 ptmalloc은 청크를 할당할 때 아무것도 없는 tcache를 참조하지 않음.)를 증가시켜준다.

#### tcache_get
```c
tcache_get (size_t tc_idx)
   assert (tcache->entries[tc_idx] > 0);
   tcache->entries[tc_idx] = e->next;
   --(tcache->counts[tc_idx]);
+  e->key = NULL;
   return (void *) e;
 }
```
tcache_get은 tcache에 있는 청크를 할당해줄 때 사용되는 함수로, next가 가르키는 청크를 할당된 청크가 있는 자리에 위치시키고 나서 count를 -1 시킨다.

#### `_int_free`
```c

|#if USE_TCACHE|
|{|
|size_t tc_idx = csize2tidx (size);|
|-|

```
`_int_free` 함수는 free를 호출하면 호출되는 함수로, count 변수가 7보다 작다면 tcache_put 함수를 호출하여 tcache에 청크를 담는다.
다음에 설명할 부분이 핵심적인 부분이다.
```c
 if (__glibc_unlikely (e->key == tcache))
+         {
+           tcache_entry *tmp;
+           LIBC_PROBE (memory_tcache_double_free, 2, e, tc_idx);
+           for (tmp = tcache->entries[tc_idx];
+                tmp;
+                tmp = tmp->next)

```
free할 chunk의 key == tcache이면 double free가 일어났다고 간주하고 프로그램을 abort 시킨다. 하지만 이 코드 이외의 double free를 막을 방법이 없는 것을 볼 수 있다.
즉, **해제된 청크의 key 값을 1비트라도 변경시킨다면 tcache에 Double Free를 발생시킬 수 있다.**

# Tcache Poisoning

tcache 연결 리스트의 `fd(next)` 값을 공격자가 원하는 주소로 조작하여  
`malloc()`이 임의 주소를 반환하게 만드는 공격 기법이다.
#### tcache_entry
```c
tcache_entry
typedef struct tcache_entry 
{
  struct tcache_entry *next; //fd의 역할을 한다
  /* This field exists to detect double frees.  */
  struct tcache_perthread_struct *key;
}
```
tcache_entry는 free 된 tcache chunk에 덮어씌워지는 구조체로 단일 연결 리스트로 구성되어있다(singly linked list). 여기서 핵심적인 부분이 단일 연결이라는 점인데, tcache는 연결이 `next`하나만 있고 LIFO 구조로 작동한다. 
그래서 chunk를 뺄 때 앞뒤 연결을 고칠 필요가 없어서 glibc는 확인할 수단이 없다. 그러면 `next`를 조작한 chunk가 첫 malloc에서 나오고, 두 번째 malloc에서 `target`이 나올 수 있다.
(Double linked list의 경우 fd와 bk를 사용해서 chunk를 빼면 앞뒤 chunk의 포인터를 이어줘야한다. 그래서 glibc가 여기를 검사하므로 poisoning이 어렵다.)

tcache에는 노드를 담을 배열이나 저장소가 없고 링크 정보를 free된 청크 안에 넣는다. 하지만 UAF가 있으면 그 공간에 직접 접근해서 `fd`를 `__free_hook`의 주소를 반환 받은뒤 거기로 system을 쓴다. malloc을 두 번 진행하여서 두 번째 청크가 `__free_hook_`을 반환하는데, 그 부분에 system을 쓰면 free('/bin/sh')이 쉘이 된다.

**단 free 된 chunk의 fd(`== next`)를 덮어쓸 수 있어야 한다.**
